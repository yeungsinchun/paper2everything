How data moves through paper2everything, and where it breaks

Three subprojects share one repo, and one data edge connects them: paper2notes copies paper2db's generated DSE crops through sync-dse.sh. paper2mock stands alone. The graph has no cycle. The weak point is that one edge: it relies on an undeclared folder layout, CI never checks it, and the Cloud Run image never includes the crops, so every DSE deck on the live site returns 404.

Every claim cites a file, or a read-only probe of the live site. The same map is in prose in docs/ARCHITECTURE.md. Annotate any box, arrow, or finding card to push back on it.

1 · The whole system on one page

Solid arrows are automated (a script or workflow). Dashed arrows are manual or agent-driven. Dashed boxes are gitignored: they exist only on a machine that generated them. Red marks the fragile or broken path; the numbered dots match the findings below.

paper2db

HKDSE Physics PDFs → classified MC/LQ banks per syllabus section.

  • Entry: ./paper2db/pipeline (--list-stages, --only, --years)
  • Tracked: paper/, metadata/*/llm_classifications.json, overrides, starts.json
  • Output: tests/sections/, tests/reconstructed/, intermediate/, .lavish/
  • Side tool: scripts/convert-qb-to-pdf.sh (not a stage)

paper2notes

Static HTML notes, Books 2 · 4 · 5, no build step.

  • Site: notes/index.html, notes/book{2,4,5}/
  • Intake: notes/_source/<book-ch>/ (tracked, never deployed)
  • Consumes paper2db via scripts/sync-dse.sh
  • Check: scripts/ci-check.mjs

Cloud Run deploy

nginx container serving paper2notes/notes/.

  • deploy.sh: build (repo-root context) → Artifact Registry → gcloud run deploy → curl checks
  • provision.sh: project, SAs, service, WIF provider
  • Root .dockerignore admits only notes + nginx.conf

paper2mock

F.1 maths mock papers in LaTeX.

  • 20 documents: f1/test1/<1..10>/{question-paper,marking-scheme}
  • Built only by compile-mocks.yml, released as two zips
  • Reads and writes only its own tree

4 · Design findings

Severity reflects impact on the monorepo's purpose, a working notes site backed by paper2db banks. Verified means checked against code or a read-only live probe on 2026-09-27. Open question marks a decision for the owner. Nothing here is fixed; that is out of scope for this change.

A1

Production never receives the DSE crops

high
generated datadeploynotes → db
What
Pages use ../_local/dse/…; _local/ is gitignored and the root .dockerignore drops **/_local/, so no image can contain the crops. The Book 5 “Export Ch.N PDF” links point there too.
Evidence
Verified: live /book5/_local/dse/mc/25/2022_q31.png → 404; /book5/ch01-…/25-1.html → 200.
Impact
The only cross-project data edge has no production path; every DSE deck shows broken images for students.
Next
Open question: may HKDSE crops be published at all? If yes, stage a paper2db export into the image; if no, hide the decks in production.
A2

A3

The notes ↔ db interface is an undeclared filesystem layout

high
fragile relative pathscoupling
What
sync-dse.sh walks paper2db's internal tree via $ROOT/../paper2db and derives the section by regex on folder names. Book folders (05_Radioactivity…) match the same ^NN_ as sections (05_Motion). Notes hardcode 82 `_local` references — 66 PNG crops in two schemes (YYYY_qN.png MC, YYYY-qN.png LQ) plus 16 combined.pdf exports.
Impact
Any rename or re-layout inside paper2db breaks notes with no error; paper2db owns no export or manifest.
Next
A paper2db export stage writing a flat tree plus a manifest; notes reference manifest keys.
A4

Nothing checks that contract

high
CInotes → db
What
ci-check.mjs skips every link through _local/ (isKnownLocalOnly) and no workflow runs paper2db. The crop choice lives in HTML, not in paper2db classification (e.g. 25-1.html shows LQ crops from section 26).
Impact
A reclassification that moves a question silently empties a deck.
Next
CI check that every notes reference exists in the paper2db manifest.
A5

Competing sources of truth feed one sync

medium
duplicated source of truthstale data
What
Sync reads tests/sections/, then legacy classified/, which overwrites fresh crops because cp -n … || cp falls through to cp. Root JSON/CSV use cp -n … || true, so they never refresh. rsync -a without --delete never prunes. Placeholders look like real data and are written with CWD-relative paths.
Evidence
Verified: macOS /bin/cp -n exits 1 and leaves the target untouched.
Next
One input (the export from A3), a clean target, and placeholders that are visibly placeholders.
A6

Four copies of every crop

medium
duplication
What
notes/_local/dse/, which no page references, plus a full mirror in each of book2, book4, book5. Book 2 holds Book 5's crops.
Next
Serve one tree from a root-relative or per-book path and drop the mirrors.
A7

The syllabus-section taxonomy has no single owner

medium
duplicated source of truth
What
SECTIONS is defined twice in paper2db (classify_mc_llm.py, classify_mc_sections.py); notes repeat section numbers in 82 `_local` references (66 PNG + 16 PDFs); sync-dse.sh hardcodes sections 20–27; the landing page hardcodes “paper2db §25–27”.
Next
One taxonomy module or JSON read by both sides.
A8

QB banks sit in paper2db but belong to nobody

medium
ownershipunversioned source
What
The “canonical” paper2db/qb/ and qb-pdf/ are gitignored; the converter is not a pipeline stage and promises an OCR step it does not run; the only consumer is notes intake. _source/*/problems.md cite paper2db/classified/mc/… 48 times, a layout the pipeline no longer writes.
Next
Open question: version QB (LFS) as a paper2db stage, or move QB handling to notes intake?

medium

Developer docs leak into the student site; docs drift

low

What
The public landing page explains the paper2db pipeline and gitignored paths, against paper2notes/AGENTS.md's no-provenance rule. paper2notes/README.md now points to ../docs/ARCHITECTURE.md §5/6 and deploy-notes.yml at the repo root (previously deploy.yml/ci.yml); the QB tables there still list QB_50x/ inside paper2notes while the canonical QB is paper2db/qb/.

What is sound

  • The dependency graph is acyclic and one-directional: paper2db never references paper2notes, and paper2mock is isolated.
  • Paid LLM classifications are tracked inputs, so rebuilds neither re-bill nor re-randomise.
  • The Cloud Run design is least-privilege: runtime SA with no roles, deployer limited to run.developer + registry writer, keyless WIF.
  • paper2mock PDFs are built and released by CI, never committed.

Decisions that belong to the owner

  1. Should HKDSE past-paper crops be served on the public site (A1)? This decides between shipping an export in the image or hiding the decks.
  2. Monorepo deploy now live at cutover 47b7788 via WIF to asia-east2/paper2notes; decide when to retire the standalone paper2notes deploy (A2 resolved).
  3. Where do QB banks live, and are the DOCX sources versioned (A8)?
