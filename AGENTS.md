# AGENTS
- `paper2notes/notes/` -> visual-html-notes skill (three.js via js/diagrams3d.js, checks via js/checks.js, KaTeX). Open `notes/index.html` (landing) or `notes/book5/index.html` etc in browser, no build. Intake is `notes/_source/<book-ch>/` (ocr.md/outline.md/problems.md/images/INDEX.md). Landing at `/` lists Book 2/4/5 with inline SVG icons; no redirect (see `paper2notes/deploy/cloudrun/nginx.conf`).
- `paper2db/` -> pipeline (`./pipeline`). Source PDFs in `paper/{mc,lq,ans}/`, generated outputs in `tests/sections/{mc,lq,items}/`, `tests/reconstructed/`, `output/` / `classified/` (legacy) and `.lavish/` — gitignored. Tracked inputs are `metadata/*/llm_classifications.json`, `metadata/derived_keys.json`, `scripts/overrides_*.json`, `tests/reconstructed/lq/*/starts.json`, `tests/reconstructed/lq/*/ans_starts.json`. QB DOCX canonical is `paper2db/qb/` (migrated from paper2notes/qb), PDFs in `paper2db/qb-pdf/`.
- `paper2mock/` -> LaTeX mocks `paper2mock/f1/test1/<1..10>/`.
- DSE wiring: `paper2notes` is read-only consumer of `paper2db`. Published snapshot `paper2notes/notes/dse/{mc,lq}/<section>/` (tracked; see `docs/ARCHITECTURE.md` §2 for publication rules) ships to Cloud Run. For local `python -m http.server --directory paper2notes/notes` preview, run `./paper2db/pipeline --force --yes` then `./paper2notes/scripts/sync-dse.sh` to populate gitignored `paper2notes/notes/_local/dse/...` and `notes/book*/_local/dse/` (so `../_local/dse/...` resolves; or `cp -r notes/dse` to `_local`). HTML DSE decks (e.g. Book 5 25.1) render in production without sync. The general link check skips `_local` via `isKnownLocalOnly`; the DSE guard checks publication contracts (see the publication rules).

Screenshots and screen captures never go in the repository. Do not commit PNG/JPG screen captures, before-after images, or any other visual evidence into the tree, and do not write bare local filenames (`before-1280.png`) into a request body — GitHub renders those as question marks. Visual evidence belongs on the forge: upload each image as an attachment (`gh pr create|edit|comment --attach '<file>#<alt>'`, which rewrites the reference to a `https://github.com/user-attachments/assets/...` URL that renders inline) and reference that attachment URL in the request body. Leave no raw link into a repository path: branch-scoped `raw.githubusercontent.com` links break the moment the branch is deleted, as happened to https://github.com/yeungsinchun/paper2everything/pull/105. This applies to every request in this repository, and the UI and crop screenshot skills below depend on it.

Lavish review boards follow the same rule. Build a board under `.lavish/`, which is gitignored, and keep it, its `before/` and `after/` copies, and its screenshots there. Never commit a board or a capture taken from one. In a request body, link the shared board URL or attach the exported captures; never link the board's repository path. Every notes HTML refactor (chapter refactor, section rewrite, template migration, visual comparison) needs a board that renders before and after side-by-side at both 1280 and 390 widths. The board contract lives in `.agents/skills/paper2everything-lavish-board/SKILL.md`; load it before building or reviewing a board.

Keep `paper2notes/notes/**/_local/` and generated `paper2db/` files out of git; `paper2db/README.md` lists the reviewed JSON inputs that stay tracked. CI is `node paper2notes/scripts/ci-check.mjs` (validates `deploy-commit-footer` per HTML and protected-text leaks; see `paper2notes/deploy/cloudrun/README.md` and `paper2notes/scripts/leak-check.mjs`, plus anchor ids/`moves.json` and answer-pointer shape; see `paper2notes/anchors/README.md`) and `node paper2notes/scripts/quiz-audit.mjs` (quiz keys, DSE availability and crop paths, plus agreement with the `dse-mc` answer store; see `paper2notes/scripts/quiz-store-audit.mjs`). Deploy is `paper2notes/deploy/cloudrun` (injects `deploy-commit-footer` via `scripts/inject-commit-footer.mjs`).

UI PRs (paper2notes HTML/CSS/JS, visuals, animations, stage): load `.agents/skills/paper2everything-ui-screenshot/SKILL.md` before launch - before/after screenshots at BOTH laptop 1280×800 and mobile 390×844 required in PR body (one pair per size, same URL/scroll/viewport, attached via `gh --attach` so they render inline - one-size-only is incomplete; checklist in skill §7) and, if video demo, both sizes via `gh --attach` unless provably invisible at one (`.agents/skills/paper2everything-pr-video/SKILL.md` §5.1/§6).

Crop PRs (question, figure, table or answer crops, DSE or QB — `paper2notes/notes/qb/crops/**`, `paper2notes/notes/dse/**`, `paper2db/tests/sections/**` and pipeline outputs): load `.agents/skills/paper2everything-crop-screenshot/SKILL.md` before launch - representative PNG screenshots required in PR body (grid or sample, before/after where changed, readable resolution, uploaded as attachments so they render inline, checklist in skill section 7). Ship briefs for crop tasks (those touching `paper2notes/notes/qb/crops` or `paper2db` pipeline crops) must name this skill.
